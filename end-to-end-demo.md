End-to-end user stories — what works vs. what's broken
  
  Story 1 — Admin sets up a connected project

  Path: Admin Console → Connectors → Projects & Sources → New Project

  What works: You can see the 3 connectors (Jira, GitHub, GitLab). You can create a project and link it to DORA + EU AI Act frameworks.

  What's broken: No Programs exist so the Project Hub shows an error. You must create a Program first or the project creation UI may not
  complete correctly.

  Fix needed: Seed 1 Program + update the 2 existing projects to use real Jira project keys (SCRUM, not BANK).

  ---
  Story 2 — Import a Jira case
  
  Path: Cases → New Case → Import from Jira → choose board → pick an issue

  What works: The Jira connector is live (12 projects visible). The board browser will load real boards from salesforceai.atlassian.net. Picking
   an issue creates a GovernanceCase with gates auto-generated by the AI pipeline.

  What's broken: The existing 5 cases use fake source keys like BANK-2401 — that Jira project doesn't exist in your real Jira. If you navigate
  to a case detail, the "View in Jira" link will 404.

  Fix needed: The demo seed must use real SCRUM or AMLDEMO epic keys from your actual Jira.

  ---
  Story 3 — Sync GitHub open PRs

  Path: Project Hub → open a project → Source Connections tab → Add Repo → Sync Now

  What works: The sync engine (/api/sync) is fully built. It fetches open PRs from bakkaiahsf/salesforce-ai-pipeline and creates
  GovernanceCases.

  What's broken: No ProjectBoard records exist (count = 0). The "Source Connections" tab on Project Hub is empty. There's no UI to add the first
   board from the Project Hub itself — you must have a board record already. Also, Sync Now writes back a governance comment to the GitHub PR,
  which may be unexpected.

  Fix needed: Seed 1 ProjectBoard linking the DORA-Q4-25 project → GitHub connector → bakkaiahsf/salesforce-ai-pipeline.

  ---
  Story 4 — Gate approval → release readiness changes
  
  Path: Cases → open a case → approve a gate → Release Readiness screen updates

  What works: GateActions, the approval route, GovernanceEvent emission — all wired.

  What's broken: After approving, the Release Readiness page must be manually refreshed (no auto-update). Also, the 5 existing cases all have
  gates in PENDING or APPROVED — none are in a narrative that tells a story.

  Fix needed: Set gate statuses so the demo starts with a clear story: 2 gates approved, 1 pending, 1 blocked → NO_GO. Approve the blocked gate
  live → CONDITIONAL. Approve the last pending → GO.

  ---
  Story 5 — Evidence submission

  Path: Evidence Hub → Submit Evidence → link to case → choose DORA control

  What works: The POST /api/evidence route is built. The Submit form in EvidenceClient works.

  What's broken: Evidence Hub is completely empty (0 items). Nothing to show before submitting.

  Fix needed: Seed 3-4 EvidenceItems with regulatory mappings (DORA Article 9, EU AI Act Article 13).

  ---
  Story 6 — AI Assurance Intelligence query
  
  Path: Intelligence → type a question → Anthropic responds with evidence-grounded answer

  What works: Anthropic is connected and the RAG pipeline is built.

  What's broken: With 0 evidence items, the RAG has nothing to retrieve. The AI will respond but will say "insufficient context."

  Fix needed: Seed evidence items first. Then the query "What DORA compliance risks exist for the Salesforce AI pipeline?" will return cited,
  grounded answers.

  ---
  Story 7 — Emergency Lock
  
  Path: Sidebar → Emergency Shutdown → Confirm → AI disabled → Unlock

  What works: Fully functional. This is the most reliable demo moment.

  Nothing broken here. This is demo-ready now.
